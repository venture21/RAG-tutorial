macOS / 맥북 설치·실행 안내
========================================

Python 3.11 권장 (3.11~3.13)과 Google Cloud CLI를 설치합니다.
Apple Silicon·Intel Mac 각각 기기에 맞는 Python으로 가상환경을 새로 만듭니다.
Python: https://www.python.org/downloads/macos/
Cloud CLI: https://cloud.google.com/sdk/docs/install

터미널(zsh/bash)에서 예시 폴더를 실제 압축 해제 폴더로 바꿔 실행합니다.
cd ~/Downloads/rag-student-studio
python3 --version
python3 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements.txt
cp .env.example .env

python3가 3.11~3.13인지 확인하고, 필요하면 설치된 python3.11 등으로 바꿉니다.
.env는 텍스트 편집기로 수정합니다. 가상환경 활성화(source)는 필수가 아닙니다.


클라우드 호출 전 준비
--------------------
.env.example을 .env로 복사한 뒤 YOUR_PROJECT_ID를 본인 Google Cloud 프로젝트 ID로 바꿉니다.
API 키·DB 비밀번호·인증 JSON은 넣지 않습니다.

gcloud --version
gcloud auth application-default login
gcloud auth application-default set-quota-project YOUR_PROJECT_ID

위 YOUR_PROJECT_ID도 본인 값으로 바꿉니다. 해당 프로젝트의 결제·Vertex AI API 사용·호출 권한을
확인하고 필요하면 프로젝트 관리자에게 요청하세요. gcloud auth login과 ADC 로그인은 별개입니다.
ADC 파일은 본인 PC에만 보관하며 배포 폴더나 ZIP에 복사하지 않습니다.
공식 안내: https://docs.cloud.google.com/docs/authentication/provide-credentials-adc


실행 명령
---------
.venv/bin/python -X utf8 check_setup.py
.venv/bin/python -X utf8 app_rag.py

종료: 실행 중인 터미널에서 Ctrl+C (macOS: Control+C).

처음 실행
---------
아래 실행 명령 후 브라우저에서 http://127.0.0.1:8000 을 엽니다.
PC 작업 폭은 1280px 이상을 권장합니다. 더 좁은 창에서는 PC 배치를 유지하며 가로 스크롤합니다.
ZIP에는 PDF가 없습니다. 본인 PDF를 화면에서 업로드하거나 pdf/ 폴더에 넣으세요.
화면 열기와 일반 디지털 PDF의 PyPDF 바로 읽기는 ADC 없이 확인할 수 있습니다.
실제 인덱싱에는 클라우드 임베딩이 필요합니다. auto 모드는 글자가 부족한 페이지를 Google에 보내 OCR합니다.
클라우드 답변도 본인 프로젝트에서 실행되므로 비용이 발생할 수 있습니다.
Ollama를 선택하면 답변 생성만 로컬이며 임베딩·필요 시 OCR은 Vertex AI입니다.

기본 설정
---------
서버는 127.0.0.1에서만 열립니다. 인터넷 공개·공동 서버 운영용 사용자 인증은 포함하지 않습니다.
100MiB·1000쪽 이하 PDF를 지원합니다. 같은 파일명은 같은 문서로 취급하므로 별개 문서는 이름을 다르게 합니다.
다중 문서 누적 인덱싱을 선택하면 이번 업로드의 페이지를 교체하고, 없는 페이지와 다른 문서는 유지합니다.
해제하면 전체 DB를 교체합니다. OCR·임베딩·저장이 실패하면 기존 DB를 유지합니다.
임베딩 모델을 바꾸려면 전체 재인덱싱하고, 질문도 저장 모델과 같은 모델을 선택하세요.
실행 데이터는 data/에 생성됩니다. RAG_DATA_DIR로 변경할 수 있고 상대 경로는 프로그램 폴더 기준입니다.
대시보드 단가는 실습용 예시이며 임베딩 토큰은 추정치입니다. OCR usage도 집계하지만 SDK 재시도·계약·할인·
실제 청구액을 모두 반영하지 않으므로 Cloud Billing과 대조하세요.
추가 파트너 모델은 본인 프로젝트의 모델 지원·리전·접근 권한을 확인한 후 선택합니다.

문제 해결
---------
- 8000 포트 충돌: .env에서 PORT=8001로 바꾸고 http://127.0.0.1:8001 로 접속합니다.
- ADC 오류: application-default login을 다시 수행하고 본인 프로젝트·권한을 확인합니다.
- 403/404 모델 오류: 모델·리전 지원과 파트너 모델 접근 가능 여부를 확인합니다.
- 429: 잠시 후 재시도하고 요청량·프로젝트 할당량을 확인합니다.
- 다른 모델/차원 오류: 저장 모델을 선택하거나 전체 재인덱싱합니다.
- 다른 OS의 .venv는 복사하지 말고 각 기기에서 새로 생성합니다.
- .env, data/, 인증 파일, 본인 PDF는 다시 공유하는 ZIP에 포함하지 않습니다.

검증 범위
---------
macOS의 Python 3.11에서 새 가상환경 설치와 오프라인 검사를 실행합니다.
Windows·Linux 실제 기기 실행과 실제 클라우드 모델 호출은 별도 확인이 필요합니다.
이 메인 서비스는 Swift, Xcode, macOS Vision, Tesseract, Docker, PostgreSQL을 요구하지 않습니다.


오프라인 검사
-------------
.venv/bin/python -X utf8 run_offline_checks.py

검사는 임시 합성 자료만 사용하고 네트워크를 차단합니다. 원본 DB·캐시는 지우지 않습니다.
Windows에서 링크 생성 권한이 없으면 링크 전용 분기만 생략하며 폴더 밖 경로 검사는 실행합니다.

선택: uv가 이미 설치된 경우
-------------------------
uv sync --locked --python 3.11
uv run --locked python -X utf8 app_rag.py
